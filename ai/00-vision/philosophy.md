# Engineering Philosophy

Software engineering is primarily about managing complexity.

Technology changes.

Architecture lasts.

---

# Simplicity

Prefer the simplest design capable of solving the problem.

Avoid unnecessary abstractions.

Complexity should be justified.

---

# Explicitness

Behavior should be explicit.

Avoid hidden magic.

Engineers should understand how the system works without guessing.

---

# Domain First

Business rules belong in the domain.

Infrastructure exists to support the domain.

Never invert this relationship.

---

# Evolution

Architecture should evolve through small improvements rather than large rewrites.

Refactoring is continuous.

---

# Quality

Code quality is a feature.

Poor architecture slows future development.

---

# AI Collaboration

AI is an engineering collaborator.

It should:

- explain
- review
- suggest
- document
- test
- optimize

AI should not make architectural decisions independently.

---

# Documentation

Documentation should explain:

WHY

before

HOW.

The reasoning behind decisions is more valuable than implementation details.

---

# Testing

Testing is documentation.

A good test explains expected behavior.

---

# Security

Security is everyone's responsibility.

Every engineer should think like an attacker.

---

# Performance

Optimize after measuring.

Avoid premature optimization.

Design for scalability.

---

# Ownership

Every module should have clear ownership.

Responsibilities must remain explicit.

---

# Continuous Improvement

Every change should improve at least one of:

- readability
- maintainability
- performance
- security
- developer experience

---

# Professionalism

Engineering decisions should be based on evidence.

Assumptions should be challenged.

Trade-offs should be documented.

---

# Final Principle

Build systems that engineers can understand ten years from now.

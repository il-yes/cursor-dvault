# C3 Collaboration Context

## Purpose

This document defines the C3 Collaboration bounded context of Ankhora.

C3 enables secure collaboration between trusted participants.

C3 answers:

> "How can people and organizations collaborate around protected information?"

---

# Mission

C3 provides the collaboration layer of Ankhora.

It manages:

- collaborative spaces
- communication structures
- participant relationships
- trust groups
- collaboration lifecycle

C3 enables cooperation without taking ownership of protected data.

---

# Core Principle

C3 is not a storage system.

C3 is not the owner of user data.

C3 coordinates collaboration around protected assets.

The ownership model remains:

```

Vault

owns information

```

coordinates collaboration

# Verified C3 End-to-End Cryptographic Architecture

The end-to-end C3 collaborative share write and read workflow is fully verified and operational:

## Cryptographic Key Hierarchy

```text
TrustGroup KEK (32-byte symmetric key)
  └─ Wraps Asset DEK (AES-256-GCM)

Member Private Key (Stellar asymmetric private key)
  └─ Unwraps Member WrappedKEK (Asymmetric Decryption) → TrustGroup KEK
  └─ TrustGroup KEK unwraps Asset DEK (AES-256-GCM)
  └─ Asset DEK decrypts Asset Payload (AES-256-GCM)
```

## Verified Workflow Execution

### 1. Collaborative Write Path (`CreateCollaborativeShareUseCase`)
* **Plaintext Source Boundary Verified**: `App.PostIPFSEntry(... IsShared: true)` stores the source entry snapshot in `PUBLIC_MODE` without vault-key encryption.
* **PUBLIC_MODE Retrieval Verified**: `GetFileFromIPFS` returns the unencrypted application plaintext JSON bytes (`c3_cid`).
* **TrustGroup KEK Resolution Verified**: Resolves existing TrustGroup KEK from creator's `VaultKeyring` using `TrustGroupID + KEKVersion`.
* **DEK Generation & Wrapping Verified**: Generates a 32-byte DEK, encrypts raw plaintext payload with DEK (AES-256-GCM), wraps DEK with TrustGroup KEK, and wraps KEK for active member devices with their public key.
* **Encrypted Asset Storage Verified**: Stores C3-encrypted data on IPFS as `ShareEntry.AssetCID` and persists `WrappedDEK` + `WrappedKEK` envelopes.
* **Zero-Knowledge Cloud Boundary**: Cloud receives zero raw KEKs, raw DEKs, or plaintext payloads.

### 2. Collaborative Read Path (`ResolveCollaborativeShareUseCase`)
* **Verified Read Sequence**:
  1. Authorize caller membership (`trustGroup.HasMember(CallerVaultID)`).
  2. Resolve active member envelope matching `CallerVaultID` and `shareEntry.KEKVersion`.
  3. Retrieve C3-encrypted asset payload from IPFS via `shareEntry.AssetCID` (`GetFileFromIPFS(... IsShared: true)` returns raw encrypted bytes without vault-key decryption).
  4. Asymmetrically unwrap `WrappedKEK` with Stellar Private Key → recovers TrustGroup KEK.
  5. Decrypt `WrappedDEK` with TrustGroup KEK (AES-256-GCM) → recovers Asset DEK.
  6. Decrypt asset payload with Asset DEK (AES-256-GCM) → recovers original plaintext bytes.
* **Round-Trip Verification**: 958-byte application plaintext payload successfully round-trips end-to-end.
* **Wails & UI Integration**: Response returned via Wails IPC to `desktopResourceService`, parsed in `C3ResourceCard`, and rendered with full mask/reveal support in `ClassicalEntryRenderer`.
